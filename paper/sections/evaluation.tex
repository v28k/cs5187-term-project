\section{Evaluation}
\label{sec:eval}

We ask four questions.
\begin{itemize}
  \item[\rqref{1}] Does the typed grammar reach more of \pg than a
    random-mutation generator in the same time: more valid statements, more
    covered lines and branches, more SQL features and plan shapes?
  \item[\rqref{2}] Which bugs does \tool find, and how precise is each oracle?
  \item[\rqref{3}] On real bugs put back into \pg, which configuration finds
    how many, and how fast?
  \item[\rqref{4}] What does the commit-directed LLM extension add, and what
    does it cost in tokens, money and repair rounds?
\end{itemize}

\subsection{Subject and Benchmark}
\label{sec:subjects}

All servers are built from \pg master \texttt{26bd08fb} (16~October~2026) with
assertions on. For \rqref{3} we built a benchmark in the style of
Magma~\cite{hazimeh2020magma} by reverting fixes: every commit between
31~July and 16~October~2026 that fixes a bug in the optimiser, executor,
parser, rewriter or a SQL-callable function, adds a regression test, and
reverts cleanly alone and together with the others, 23 in all. We build the
\emph{fixed} server, one \emph{solo} server per bug (only that fix reverted),
and the \emph{injected} server (all 23 reverted) on which the campaigns run.
A proof of concept (PoC) written from each regression test changes its result
for 20 bugs: 8 wrong results, 5 internal errors, 4 assertion failures, 2
missing errors and 1 wrong error. A crash-only fuzzer can see only the 9
assertions and internal errors. The other three change only the plan, or need an
equality operator that returns NULL for non-NULL inputs, and leave the
denominator. On the injected server every PoC shows the symptom of its solo
server.

\subsection{Configurations}
\label{sec:baselines}

Every configuration (\emph{arm}) uses the same server, schema, executor,
oracles, time budget and per-trial seed; the arms differ only in the generator
and in what it can attach. \arm{Random} is a mutation-based generator that
edits seed queries at the token level and cannot attach metamorphic checks.
\arm{Grammar} is Step 1 alone. \arm{Grammar+Oracles} adds Steps 2--4: metamorphic
checks (including RLS and CERT) on half the queries, plan-shape guidance,
feedback weights and data-profile literals; \arm{Grammar+Oracles, flat} is the
same without the weights. \arm{+LLM} adds the fragments, seeds and rewrites that
passed the \gate, and \arm{+LLM fragments} and \arm{+LLM seeds} use one of
them. The LLM never sees the 23 benchmark fixes: the commit miner excludes
them. All arms run with the plan-variant oracle and, in \rqref{3}, the
cross-version oracle, because these do not depend on the generator.

\subsection{Setup}
\label{sec:setup}
\tool is about 10{,}500 lines of Python with 148 unit tests and a 628-line
grammar; it drives \pg through \texttt{psycopg} and reads the server log for
assertion and crash evidence. Each arm runs 5 trials of one hour, with four workers in parallel and one
server per worker. \rqref{1}, \rqref{2} and \rqref{4} ran on one laptop (WSL2,
24 logical cores), \rqref{3} on another; the arms of one experiment never share
a machine, so throughput and coverage are comparable within an experiment.
The cross-version reference is \pg 18.6. Following
Klees et al.~\cite{klees2018evaluating}, and Arcuri and
Briand~\cite{arcuri2011practical}, we report medians, compare arms with the
two-sided Mann--Whitney U test, and give the Vargha--Delaney
$\hat{A}_{12}$ effect size~\cite{vargha2000a12}. With 5 trials per arm the
smallest possible two-sided $p$ is 0.008, so we read effect sizes, not only
$p$. Coverage is sampled every 300 seconds per worker, so the first point of every curve is the server's start-up coverage.

\paragraph{The language model.} The client has an API mode and a manual mode (the
prompt is written to a file and the answer read from a file). We had no access to
Claude for the evaluation, so a script answered the manual prompts with Google
Gemini Flash models on the free tier: 9 answers by \texttt{gemini-3.6-flash}, 2 by
\texttt{gemini-3.8-flash} and 14 by \texttt{gemini-3-flash-preview}, each taking
over when the previous model's daily quota ran out or it was overloaded. The quota
limits the \rqref{4} run to 10 of the 25 mined commits. The tool is unchanged;
the results of \rqref{4} are results for these models, and a stronger model may
do better.

\begin{observation}
\label{obs:grammar}
The typed grammar reaches far more than random mutation: 36.7\% against 22.2\%
of lines ($\hat{A}_{12}=1.00$, $p=0.008$), 101 against 23 SQL features, and
99.3\% against 26.0\% valid statements, although the random arm runs 15 times
more test cases.
\end{observation}

\begin{observation}
\label{obs:oracles-reach}
The oracles do not add line coverage (36.7\% to 36.2\%, $p=0.42$) but they
roughly double the plan shapes (20{,}279 to 34{,}313, $\hat{A}_{12}=0.84$,
$p=0.095$, so with 5 trials this is an effect size, not a significant
difference). The feedback weights contribute: without them the same arm
reaches 23{,}997 plan shapes ($\hat{A}_{12}=0.80$, $p=0.15$), at the price of
validity (96.3\% against 99.4\%, $p=0.016$).
\end{observation}

Oracles also cost throughput: the plan-variant runs and metamorphic checks
lower the statements per second from 67 to 40.

\subsection{\rqref{2}: Bugs and Oracle Precision}
\label{sec:rq2}

Across the \rqref{1} and \rqref{3} campaigns, plus the earlier hunt and smoke
runs, \tool reported 93 distinct bug candidates (after de-duplication by
signature). We triaged all of them (Section~\ref{sec:triage}) and

\paragraph{Bugs.} Four bugs found by \tool were not known when we found them.
(1)~The wrong result of Figure~\ref{fig:motivating}, found by the \texttt{(SELECT
e)} rewrite (BUG~\#19793, with a patch). (2)~\texttt{JSON\_TABLE} does not assign
collations to its context item and \texttt{PASSING} arguments (BUG~\#19768; 10
signatures). (3)~\texttt{MERGE} into a partitioned table fails with ``SubPlan
found with no parent plan'' (BUG~\#19802), found by \arm{Grammar} and
\textbf{confirmed by a \pg committer} who posted a patch. (4)~A parallel
\texttt{Append} assertion (BUG~\#19803), found by \arm{+LLM fragments} through a
TLP check, \textbf{confirmed by a committer and fixed on master}. The oracles
also rediscovered four bugs that others had reported days earlier: a wrong
result of self-join elimination under \texttt{ROLLUP} (BUG~\#19800, found by
toggling \texttt{enable\_self\_join\_elimination}, present in 18.6), a corrupt
\texttt{MVNDistinct} entry (\#19772, via the \texttt{(SELECT e)} rewrite),
\#19784, and a \texttt{to\_char} bug whose consequence is an assertion in
\texttt{NORMALIZE} (\#19771, fixed upstream).

\begin{observation}
\label{obs:wrong}
Plan-variant and metamorphic oracles found real wrong results in released
versions that no crash oracle can see (BUG~\#19793 and \#19800).
\end{observation}

\paragraph{Precision.} Of the 93 candidates, 28 (30\%) did not reproduce in
three re-runs and 6 are open. Of the 59 decided, 7 are real, 15 are duplicates
of real bugs and 37 are false positives, so the precision is $7/44=0.16$ without
duplicates and $22/59=0.37$ if duplicates count as true positives. The false
positives come from few classes. Six were found in development and fixed
before the campaigns; the campaigns revealed four more, fixed \emph{after} the
runs and tested on the stored reproducers and unit tests, but not re-measured.
(1)~\emph{Equal intervals with different text} (16 candidates: \texttt{MODE()},
\texttt{UNION}, \texttt{INTERSECT ALL}): the keys were equal values printed as
\texttt{00:00:00} or \texttt{6 days -144:00:00} depending on join order; the
digest now uses \pg's own interval equality. (2)~\emph{Order-sensitive
aggregates whose key is not the value}, such as \texttt{JSONB\_AGG(x ORDER BY
NULL)} (2). (3)~\emph{State divergence in the cross-version oracle} (5): an
\texttt{INSERT} using \texttt{LAG(\ldots) IGNORE NULLS}, which exists only on
master, succeeds there and fails on 18.6, so later comparisons differ; the
oracle now stops comparing after such a statement. (4)~\emph{An LLM rewrite that
is not an identity} (Section~\ref{sec:rq4}). After these fixes every decided
candidate left is real; five RLS candidates and one \texttt{corr()} case remain
open.

\begin{observation}
\label{obs:rq3}
With one hour and five trials, the arms found few of the benchmark bugs:
\arm{Random} 0 of 20, \arm{Grammar} 1, \arm{Grammar+Oracles} 2 and \arm{+LLM}
2. No arm found any of the 8 wrong-result bugs.
\end{observation}

The grammar arms found the internal error of fix \texttt{dfcf6fa7} in nearly
every trial (median 458, 509 and 1{,}109 seconds); \arm{Random} never did. The two
arms with oracles also found the assertion of \texttt{11b56ee2}, once each, which
is too little to separate them. The benchmark therefore does \emph{not} show an
advantage of the oracles; that claim rests on \rqref{2}. Three things limit
\rqref{3}: one hour is short for bugs that need a specific combination of
features; attribution is conservative (of the 30 wrong-result failures, 11
reproduce on the fixed server, 19 on no server, and none on a solo server); and
five trials cannot separate arms that find a bug in one trial in five.

\subsection{\rqref{4}: The LLM Extension}
\label{sec:rq4}

The ledger of the Gemini Flash run (Section~\ref{sec:setup}) shows that the gate
accepts 4 of 10 commits (2 in the first round, 1 in the second, 1 in the third).
Of the 25 rounds, 16 were rejected because too few of the fragment's statements
ran on the server, 2 each because the fragment was never derived or did not
parse, and 1 on seeds or coverage; the mean validity of a proposal is 36.5\%.
The run used 328{,}000 input, 171{,}000 output and 47{,}000 cached tokens and
cost nothing on the free tier, and all 7 proposed rewrites passed the gate.

\begin{observation}
\label{obs:llm}
The LLM arms add SQL features (101 to 104--106, $\hat{A}_{12}=1.00$,
$p=0.004$) but no coverage: lines drop from 36.2\% to 35.7\% ($p=0.42$), plan
shapes from 34{,}313 to 26{,}375, and validity from 96.3\% to 95.3\%.
\end{observation}

The extension covers only 34 more changed lines over the 10 commits. Seeds
alone give the best validity of the three arms (98.3\%) with as many features as
both; the fragments-only arm found BUG~\#19803. The extension is cheap and
safe, but with these models its benefit is modest.

\paragraph{The gate is not enough for rewrites.} The gate accepted all 7
proposed equivalence rewrites, and one of them,
\texttt{NULLIF(\{e\}, NULL::text COLLATE "POSIX")}, is not an identity: it
changes the collation, so \texttt{UPPER} of the rewritten expression differs.
It caused a false positive in \rqref{3}. The value probe evaluates the rewrite
on values and the live checks on test cases, but neither varies the collation.
The gate now rejects an explicit \texttt{COLLATE}. Testing a claimed equivalence on samples is not proof.
